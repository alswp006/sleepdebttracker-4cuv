# Architecture Review
Generated: 2026-07-30T19:52:39.354Z
Score: 68/100

## Summary
The codebase is a small React SPA (App-in-Toss mini-app) with a clean layered structure (pages → hooks → lib) and no circular dependencies, and a nice 'pre-built component' library convention in src/components. However, there is meaningful duplication of small utility logic (haptic wrapping, today-date helpers, tab config, formatting) copy-pasted across 4-6 files instead of being centralized, import-path style is inconsistent (relative vs '@/' alias) even within the same file, and a handful of exported utilities/types appear to be dead code. None of these are critical, but they add maintenance risk as the app grows.

## Issues
### Warnings
- [duplication] A nearly identical 'try/catch around generateHapticFeedback, swallow throw outside WebView' wrapper (safeHaptic/fireHaptic) is independently reimplemented in six places instead of one shared helper. — Files: src/pages/Home.tsx, src/pages/RecordPage.tsx, src/pages/SettingsPage.tsx, src/pages/SleepTypePage.tsx, src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx / Fix: Extract a single `fireHaptic(type)` (or `useHaptic()`) helper into e.g. src/lib/haptics.ts that wraps generateHapticFeedback with the try/catch guard, and import it everywhere instead of redefining it per file.
- [duplication] The bottom tab configuration array (TAB_ITEMS: 홈/리포트/플랜/설정) is copy-pasted verbatim in four page files. — Files: src/pages/Home.tsx, src/pages/PlanPage.tsx, src/pages/ReportPage.tsx, src/pages/SettingsPage.tsx / Fix: Move TAB_ITEMS into a single shared module (e.g. src/lib/navigation.ts or alongside FloatingTabBar.tsx) and import it from all four pages so route changes/relabeling happen in one place.
- [consistency] Import path style is inconsistent — some files use the '@/...' alias and others use relative paths ('../lib/utils', './Card', './pages/Home') for equivalent imports, sometimes within the same file (App.tsx mixes relative page imports with an '@/lib/settingsStore' alias import). — Files: src/App.tsx, src/components/Amount.tsx, src/components/CountUp.tsx, src/components/ScreenScaffold.tsx, src/components/SummaryHero.tsx / Fix: Standardize on the '@/' alias for all cross-folder imports (reserve relative imports only for same-folder siblings) and enforce via an eslint import/no-restricted-paths or import-order rule.
- [consistency] Error-handling pattern is inconsistent between lib modules: storage.ts/settingsStore.ts/records.ts use a Result-object pattern (SaveResult {ok, reason}) that never throws, while calc.ts's calcSleepMin throws a raw Error('INVALID_DURATION') for bad input, and records.ts calls it directly with no try/catch — mixing throw-based and result-based error handling in the same save flow. — Files: src/lib/calc.ts, src/lib/records.ts, src/lib/storage.ts / Fix: Pick one convention — either have calcSleepMin return a Result type (consistent with SaveResult) or have saveRecord explicitly catch and translate the throw into an SaveResult{ok:false, reason:'INVALID_DURATION'} — and document it as the standard for all lib functions.
